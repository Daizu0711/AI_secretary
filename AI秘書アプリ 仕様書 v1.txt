AI秘書アプリ 仕様書 v1
2026-11-04 時点。状態: 仕様確定。フェーズ①は実装済み。フェーズ②の一部(タイムライン、固定枠の自動計画、ロック画面)は index_1.html に実装済み。
1. 目的と前提
• 自分専用のAI秘書。Winter Arcアプリとは別アプリで、運動・食事・睡眠などWinter Arcの機能は入れない
• 用途は3つ: タスク・予定の管理、勉強・課題の管理(IB)、1日の計画と意思決定の相談
• 端末はiPhone・iPad・MacBook(使用頻度は同程度)。3台で同期する
• 完全無料で運用する。Apple Developer Programには加入しない
• 技術的な判断はClaudeに任せる。仕様を先に詰め、確定してから実装する
2. 全体構成
• フロント: 単一HTMLのPWA。GitHub Pagesで公開し、各端末のホーム画面(MacはDock)に追加する。デザインはボーンホワイト地+オレンジ、liquid glass
• バックエンド: Supabase無料枠(Auth、Postgres+行単位アクセス制御、Realtime、Edge Functions、Storage)。秘書用テーブルは sec_ 接頭辞。ManageBac課題のテーブルだけWinter Arcと共有する
• AI: Edge Function ai(AIルーター)。APIキーはSecretsに保管し、端末には置かない
• ManageBac取り込み: GitHub Actions(privateリポジトリ)が、前に作ったPythonスクレイパーを数時間おきに実行する。学校のID/パスワードはGitHub Secretsに預ける
• Hermes: 別PC(Windows/Linux、WSL2想定)で動くエージェント。Supabaseのジョブ表を介して連携する
• iMessage中継: 専用のMacBook Air(M2、macOS 15)+BlueBubbles
• ネイティブ(Swift): フェーズ④の薄い層。ウィジェットとバックグラウンド録音だけ
3. 認証とセキュリティ
• ログインはメール+パスワードのみ。Face ID・パスキーは不要と決定した
• ログイン画面はHITMAN風(PASSWORD枠、ACCESS GRANTED / DENIED、WELCOME演出)。メールは端末に保存し、2回目以降はパスワード枠だけ
• 自分のアカウントを作成したら、Supabaseの新規登録をOFFにする(公開URLからAIのキーを使われないため)
• 行単位アクセス制御(RLS)で、自分の行だけ読み書きできる
• AIは追加・変更・削除・完了を勝手に確定しない。すべて「提案→承認→適用」で、直後は元に戻せる
• 外部通知(iMessageなど)にはタイトルと期限だけを載せ、本文は載せない
• メモ・タスク単位の「AIに見せない」フラグを持つ。Gemini無料枠は入力が学習に使われる可能性があるため
• AI呼び出しの成否は sec_ai_log に記録する
• Hermesへの依頼窓口はPC操作の入口になるため、許可リスト・隔離フォルダ・破壊的操作の承認・実行ログを必須にする
4. 機能仕様
4.1 タスクとメモ
• タスク: タイトル、期限、カテゴリ、見積り時間(分)、優先度、完了、AI非公開フラグ
• メモ: タイトル、本文、カテゴリ、AI非公開フラグ
• 画面: 今日 / タスク / メモ / 設定(+チャット)。検索、バッジ、元に戻すトースト
4.2 AIチャット(承認制)
• 読み取り(list_items)は即実行。書き込みは propose_ 系ツールで提案カードを出し、承認で適用する
• 提案の種類: タスク追加、メモ追加、更新、完了、削除、記憶の保存
• 計画相談・要約・進捗確認では、先にタスクとメモを読んでから答える
4.3 AIの記憶
• 好み、固定予定、勉強のペースなどを、承認制で保存する。一覧で確認・追加・削除できる
4.4 音声入力
• Web Speech APIで日本語を認識して送信。使えない環境ではキーボードのマイクで代用する
4.5 端末別の画面
• iPhone: 1画面+下タブ。今日のタイムライン、次の1件、音声入力
• iPad: 左にタイムライン/一覧、右にチャットの2ペイン
• Mac: サイドバー+一覧+チャットの3ペイン。⌘Kでクイック追加
4.6 今日の計画とタイムライン
• 対象はManageBacの課題+自分で入れたタスク全部(学校以外も混ぜる)
• 条件は、期限、課題の重さ、その日の使える時間。使える時間は毎回聞く(1h/2h/3h/4h以上のチップ)
• 朝にActionsが仮の使える時間(その曜日の前回値、なければ2時間)で仮プランを作り、アプリを開いて時間を選ぶと即再計算する
• 時間指定のあるものはWinter Arc風の縦タイムラインに表示し、時間なしは「今日のリスト」に出す
• 勉強ブロックは空き枠に薄く「提案」として配置し、タップで確定する。予定が押した時は組み直し案を出す。休憩と集中ブロックも計画に含める
• 課題の重さ(所要時間・重要度)はAIが推定し、あとから自分で直せる。直した値を優先する
4.7 学習系
• 見積り学習: 完了時に実績時間を記録し、科目・種別ごとに「見積り÷実績」の補正値を更新して次回以降の見積りに掛ける。精度の推移をグラフで表示
• 間隔反復: メモ・録音の要約・授業内容からAIが復習カードを作り(承認制)、忘却曲線ベース(FSRS系)で復習タイミングを決める。今日の計画に「復習◯枚・約◯分」を入れる
• どちらもアプリ側で計算し、Hermesが止まっていても動く
4.8 EE / IA / TOK などのプロジェクト管理
• 段階: テーマ決定 → リサーチ → 構成 → 初稿 → フィードバック → 改稿 → 最終
• 項目: 語数/目標語数、マイルストーン、指導者フィードバックの記録、ManageBacの課題との紐づけ
• 進度は、段階・語数・マイルストーン消化率から計算し、全体を1画面のダッシュボードで見せる。遅れは警告し、今日の計画に「このプロジェクトを◯分進める」ブロックを自動で混ぜる
• 入力は手動が基本。EEだけ、後からEE Scholarが語数をSupabaseへ送る連携を足せる。Googleドキュメント連携は見送り
4.9 課題支援(NVIDIA NIM)
• 通常の宿題: 下書きを作らせてよい(NIM優先)
• EE / IA / TOK: 構成案、論点出し、質問、フィードバック、次にやることのヒントまで。本文の代筆は既定でオフ。IBの学問的誠実性規定に触れ得るため、使う場合も出典明記が必要で、学校の方針も確認する
• AI利用の記録(日時・用途・出力)を自動ログし、申告や引用に使えるようにする
4.10 録音・文字起こし・要約(iPadとMacのみ)
• アプリ内で録音(Wake Lockで画面を点灯したまま)。1時間超は分割アップロード
• Supabase Storageに保存し、Edge Function経由のGeminiで文字起こし・要約・タスク候補抽出(承認制)
• iPhoneにはボタンを出さない。画面ロック中の録音はフェーズ④のSwiftで対応する
4.11 NotebookLM
• 個人版に公式APIがなく、埋め込みは期待しない。科目・プロジェクトごとにノートブックのURLを登録し、アプリからワンタップで開く
• 文字起こし・要約・ヒント履歴を、ソース追加用のMarkdownとして書き出す
• 自動投入(非公式ライブラリ)はHermes側のPCでの任意機能で、既定はオフ。壊れやすく規約上のリスクもある。失敗時はアプリに通知し、書き出しでの手動追加に切り替える
4.12 その他
• 繰り返しタスクと習慣、週次レビュー(完了/未完了と来週の見通し)、全文検索、JSONエクスポート
• Googleカレンダー連携は最後のフェーズ。予定を読み込んでタイムラインに表示する(読み込みのみ)
5. 通知設計
• 段階1: Web Push(Supabase Edge Function+pg_cronが毎分、近い予定を確認して送信)
• 段階2: 確認タップがなければ数分後にiMessage。確認を押した時点で止まる
• 段階3(Airがオフライン時): Web Pushを短い間隔で再送し、アプリ内にバナーを出す
• LINEと電話は使わない。予備が必要になったらTelegramかメールを追加できる
• 重要の既定: 提出期限が近い未完了課題、時間指定の予定の直前、ManageBacの新規課題・期限変更、プロジェクトの遅れ、取り込みやHermesジョブの失敗、ログイン異常。条件と静音時間帯は設定で変更できる
• iMessage中継: BlueBubblesをMacBook Airで常時起動(電源接続・スリープ無効)。通信はAirからSupabaseへの外向きのみで、ポート開放は不要
• 送信元は秘書専用の新しいApple ID(自分宛てだと通知が鳴らない可能性があるため。要実機確認)
• まずPrivate APIなしで試し、不安定ならこのAirだけSIPを無効化する
• 返信コマンドは、完了 / 先送り / 追加 ◯◯ / 今日の計画 / 状況 のみ。送信元は自分に限定し、強い操作は受け付けない
• Airにハートビートを送らせ、5分途切れたらWeb Pushで通知する
6. フォールバック設計
• AIルーター: チャット/計画は Gemini → NVIDIA NIM → Hermes(オンライン時)。課題ヒントは NIM → Gemini。文字起こし・要約は Gemini → 録音を保存して後で再処理
• 429やタイムアウトは再試行し、失敗が続いた提供元は10分休ませる
• ManageBac取り込みが失敗したら、最後の成功データを「最終更新◯時間前」付きで表示する
• オフライン時は閲覧と追加キューだけ動かし、復帰後に同期する
• Hermes PCがオフラインなら、その機能だけ無効にして他は動かす
• ネイティブが失効している週は、PWAで使える
7. Hermes連携
• アプリがSupabaseのジョブ表に依頼を書き、PC側のHermesが取得して結果を書き戻す。PCの公開は不要
• ジョブ種別: 夜間レビュー(進捗分析・メモ整理・週次レビュー)、NotebookLM代行、自由依頼(開発など学習以外も)
• 自由依頼はPC上の隔離フォルダ内のみ。ファイル削除・外部送信・コマンド実行は、アプリで承認タップするまで実行しない。未知のジョブ種別は拒否する
8. データモデル
• 現状: sec_items(種別、タイトル、本文、期限、カテゴリ、見積り、実績、完了、AI非公開、scheduled_start / scheduled_end / priority)、sec_memory、sec_ai_log
• 追加予定: ManageBac課題(共有)、プロジェクトとマイルストーン、復習カード、時間ログ、Hermesジョブ、Web Push購読
9. 実装状況とロードマップ
• 実装済み: 同期、タスク/メモ、承認制AIチャット、AIの記憶、音声入力、パスワードログイン、HITMAN風ロック画面、端末別レイアウト、AIフォールバック、エクスポート、今日のタイムラインと固定枠の自動計画(要 phase2.sql 実行)
• 次: 使える時間の入力と再計算 → ManageBac取り込み → 見積り学習
• その後(提案順): Web Push+iMessage通知 → プロジェクト管理と課題支援 → 録音・要約 → 復習カード → Hermes・NotebookLM → Swift(ウィジェット、バックグラウンド録音) → Googleカレンダー
• Swiftは無料署名のため7日で失効する。MacBookから週1回の自動再ビルドを入れ、PWAは常に使える状態にしておく
